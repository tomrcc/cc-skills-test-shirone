Consumed via `getSortedPosts()`/`getSortedPostsList()` in `src/utils/content-utils.ts`. Body rendered as a page by `src/pages/posts/[...slug].astro` (`<Content />` inside `Markdown.astro`, or inside `EncryptedContent` for encrypted posts). When `permalinkConfig.enable` is true, `src/pages/[...permalink].astro` builds `/<format>/` URLs instead (disabled now).
- **spec** — `src/content/spec`, `**/*.{md,mdx}`, empty schema. One file, `about.md`, body rendered by `src/pages/about.astro` via `getEntry("spec", "about")`. Title/description of `/about/` come from `aboutConfig` (`$t:` i18n refs).
- **series** — `src/content/series`, `**/*.md`, flat (slug = route segment). 2 files. Schema: `title`, `status` (`ongoing|completed`), `defaultCategory`. Body is an optional overview rendered by `src/pages/series/[slug]/index.astro`. Posts join by `series: <slug>` (reverse lookup; series files don't list posts — already one canonical side).
- **moments** — `src/content/moments`, `**/*.md`, flat, 6 files. Schema: `published`, `pinned`, `location`, `mood` (Iconify name), `tags[]`, `images[{src, alt}]` (public paths), `encrypted`, `password`, `passwordHint`, `draft`. No pages of their own; listed with bodies on `/moments/` (`getSortedMoments()`), so a data-and-body collection: `_enabled_editors: [content, data]`, `disable_url: true`.

Content outside Astro collections:

- **snippets** — `src/content/snippets/include-example.md`, pulled into posts by `<!-- @include: ../snippets/include-example.md -->` (remark-includes). Not an Astro collection; no page. Editable markdown fragment → collection with `disable_url: true`.
- **albums** — `public/images/albums/<Album>/info.json` (4 albums: `AcgExample`, `EncryptedExample`, `ExternalExample`, `HiddenExample`), scanned by `src/utils/album-scanner.ts`; each builds `/albums/<Album>/`. Folder also holds `README.md` and `AGENTS.md` (shipped to `dist/`; glob must target `*/info.json`).
- **Data files** (`src/data/*.ts`, TypeScript arrays typed from `src/types/*`): `projects`, `skills`, `timeline`, `devices`, `friends`, `games`, `compass`, `anime`, `music`. Like-shaped records; `projects` items carry a `key` id. `src/data/anime-snapshots/` is generated (gitignored). Read by feature pages through `src/utils/feature-data.ts` with filters/ordering from the matching `*Config`.
- **Site settings** (`src/config/*Config.ts`, ~35 domains) — each wraps its defaults in `withUserConfig("<domain>", {...})`. The theme ships a YAML overlay: in `external` content mode, `config/<domain>.yaml` files are type-checked and compiled by `scripts/content/sync.mjs` into `src/user/user-config.ts`, then deep-merged (objects merge, arrays replace). - **UI strings** — `src/i18n/languages/{en,es,id,ja,ko,th,tr,vi,zh_CN,zh_TW}.ts` (~316 keys each). The site renders one UI language, `siteConfig.lang: "en"`; posts may set `lang`. No per-locale routes or content. `i18nConfig` (`i18n.yaml` in overlay mode) can override strings per locale.

Existing CMS config: `frontmatter.json` (Front Matter CMS) for posts — useful as a field-type reference; leave it.

## 3. Pages and routing

`trailingSlash: "always"`, `build.format` default (directory), `site: https://shirone.mysqil.com/`, `base: /`, output static. All set in `src/integration/index.ts` from `siteConfig` / `integrationsConfig.ts`; `astro.config.mjs` only calls `shirones()`.

Every route in `src/pages/`:

- `posts/[...slug].astro` — `/posts/<id>/` for each non-draft post (19).
- `[...permalink].astro` — custom permalink URLs; builds nothing while `permalinkConfig.enable` is false.
- `about.astro` — `/about/`: `spec/about.md` body + `aboutConfig` title/description.
- `albums.astro` — `/albums/`: album index (`AlbumSection.svelte`, `client:visible`).
- `albums/[id]/index.astro` — `/albums/<id>/` per `info.json` (4). Protected albums encrypt their payload at build (`ProtectedAlbum.svelte` `client:load`; `AlbumGallery.svelte` `client:only="svelte"`).
- `anime.astro` — `/anime/`: `animeConfig` + `src/data/anime.ts` (source `local`; Bangumi/Bilibili snapshots optional).
- `archive.astro` — `/archive/`: generated listing (`ArchivePanel.svelte`).
- `categories.astro`, `tags.astro` — generated taxonomy pages (no per-term pages).
- `compass.astro`, `devices.astro`, `friends.astro`, `games.astro`, `projects.astro`, `skills.astro`, `timeline.astro` — feature pages: `<feature>Config` (enable, title, description, categories, ordering, `disabledKeys`) + `src/data/<feature>.ts`, rendered by a `*Section.svelte` organism with `client:visible`.
- `moments.astro` — `/moments/`: moments collection listing (`MomentSection.svelte`, `client:visible`).
- `series.astro` — `/series/`: generated series index. `series/[slug]/index.astro` — `/series/<slug>/` (2).
- `rss.astro`, `atom.astro` — feed guide pages (i18n copy). `404.astro` — i18n copy.
- Endpoints (build-time, no editing): `rss.xml.ts`, `atom.xml.ts`, `llms.txt.ts`, `llms-full.txt.ts`, `robots.txt.ts`.

Feature pages return 404 / drop from nav and sitemap when their `enable` is false (`sitemapFilter.ts`, `pruneUnavailableNavLinks()`). No redirects in config. No API or server routes.

Built baseline: 47 HTML files in `dist/`.

## Primitive-vs-computed census

`src/pages/posts/[...slug].astro` (and its twin `[...permalink].astro`):

| Interpolation | Kind | Action |
| --- | --- | --- |
| `{entry.data.title}` | primitive text | keep — primitive editable |
| `<Content />` in `Markdown.astro` | body | `@content` candidate (custom unified processor; see Flags) |
| `PostMetadata published/updated/tags/category` | computed (formatted dates, links) | registered component or leave uneditable |
| `ImageWrapper src={entry.data.image}` | computed (asset resolution, responsive) | image editable on the wrapper / registered component |
| `formatDateToYYYYMMDD(entry.data.published)` | computed | leave (data panel) |
| `EncryptedContent password/hint` + `<Content />` | computed (encrypted at build) | not editable in the Visual Editor |
| `nextTitle`/`prevTitle`/`getPostUrlBySlug(...)` | computed (build-filled) | leave |

`src/pages/series/[slug]/index.astro`: `{series.data.title}` primitive; subtitle (status label + count) computed; body `<Content />` → `@content`.

`src/pages/albums/[id]/index.astro`: everything comes from `album-scanner` (computed); edit through the album collection.

Feature pages pass whole arrays into Svelte organisms; there are no `{data.x}` interpolations in those route files.

## 5. Build pipeline

- `build`: `node scripts/content/sync.mjs && astro build && npx pagefind --site dist && node scripts/fonts/check-fonts.mjs`. CloudCannon build command: `pnpm build` (via the pinned pnpm). Output `dist`.
- `content:sync` is a no-op in `local` mode; in `external` mode it materialises content and compiles the YAML config overlay (runs `tsc` type checks).
- Build-time generation (all gitignored, none edited by editors): icon collection (`src/generated/`), font subsets (`src/assets/fonts/.subset/`), moment thumbnails (`public/assets/moments/thumbnails/`), Pagefind index (`dist/pagefind`).
- No env vars needed for the build. Optional: `CONTENT_DIR` / `CONTENT_REPO_URL` / `SHIRONE_CONTENT_SYNC` (content separation), `BILI_SESSDATA` (manual `anime:sync` only), font budget overrides.

- Validation commands from AGENTS.md (run as `corepack pnpm …` here, not `.cmd`): `astro check` (0 errors), `exec biome ci ./src`, `check:manifest`, `check:package-manifest`, `type-check`.

## Flags and special patterns

- **Integration wiring lives in `src/integration/`.** `editableRegions()` and anything else for CloudCannon must be added there (not `astro.config.mjs`), and keep package mode working (`docs/packaging-contract.md`, `rules/project-rules.md` §12). AGENTS.md's "zero extra burden" rule applies to optional client code.
- **Astro 7 / Vite 8 with `@cloudcannon/editable-regions`** is untested here; verify the integration installs and builds early in Phase 4.
- **Custom `markdown.processor`:** `@content` live re-rendering must reproduce directive output; check in Phase 4.
- **Swup** intercepts navigation; the Visual Editor loads each page directly. Persistent shell state syncs on Swup hooks.
- **Build-time icon collection and font subsetting:** an icon name or new glyph chosen in the editor only renders after a rebuild; a live re-render of a Svelte component with a new icon may show nothing.
- **`src/assets` images resolved by `import.meta.glob`:** newly uploaded `src/assets` images appear after rebuild.
- **Encrypted posts/moments/albums:** bodies/photos are encrypted at build; passwords sit in plaintext front matter / `info.json` (already true in the repo). Their bodies aren't editable in the Visual Editor.
- **String references:** post `series` → series filename slug; `category`, `tags`, series `defaultCategory` are free strings; moment `mood` and data `icon` are Iconify names.
- **`set:html`:** `Layout.astro`, `FooterBar.astro` (footer HTML), comment embeds, music sidebar, post/about/series routes (stylesheet/asset injection).
- **Folder-per-post:** `guide/` and `image-grid-demo/` keep co-located images.
- **Styled HTML in front matter:** none found; `banner.homeText.subtitle` strings are plain.
- **Existing CMS:** `frontmatter.json` (Front Matter CMS).

## Decisions and why

1. **Keep the theme's model; no page builder.** Routes are thin by the site's rules, data-driven, and shared with package mode; a page builder would fork the theme's layouts and break the `shirones` contract. Editors get inputs through settings and data files instead.
2. **Site settings: use the theme's own YAML overlay.** Recommended mechanism: a `shirone.content.json` with `source: { type: "path", path: "<in-repo folder>" }` and the `content`, `data`, `assets`, `public` mounts set to `false`, so `content:sync` only compiles `<folder>/config/*.yaml` into `src/user/user-config.ts`. This reuses the documented, type-checked overlay instead of rewriting `src/config/*.ts`, and `src/config/` stays the defaults + docs source. Phase 2 must confirm with a minimal test that `sync.mjs` accepts a path source with only the config mount, that `pnpm build` regenerates the overlay, and that CloudCannon's edits to the YAML show after rebuild. Fallback if it fails: JSON/YAML data files imported by each `*Config.ts`.
3. **Editor-facing settings domains** (exposed as YAML): site (title, subtitle, banner, theme colour, lang), profile, announcement, nav-bar, footer (+ `footer.html`), sidebar, post-list, article, license, series, about, friends, moments, albums, compass, projects, skills, timeline, devices, games, anime (title/description/categories/order/`disabledKeys`), llms. Developer-only (stay in code): integrations, fonts, expressive-code, image-bloom, FAB, context-menu, permalink, comment/umami credentials, music provider, i18n.
4. **Feature data (`src/data/*.ts`) → JSON or YAML files** that the existing `.ts` modules import and re-export with their types, so consumers and package-mode overrides (`shirones/config/data/<name>.ts`) keep working. Data collection(s) with `disable_url: true`; arrays stay top-level arrays with `key` ids where they have them.
5. **Locales stay as they are.** The ten `src/i18n/languages/*.ts` modules remain developer-owned TypeScript; `siteConfig.lang` stays a site setting; post `lang` stays a front matter field. No new locales, no locale routing, no `i18n.yaml` exposure unless the user asks.
6. **Hosting on CloudCannon, static output.** No headers/redirects to port. No forms to wire to Inbox.
7. **Package manager:** `npx pnpm@11.28.2 install --frozen-lockfile`, `pnpm build`, output `dist`.
8. **Albums** become a collection over `public/images/albums/*/info.json` (`disable_url` off; URL `/albums/<folder>/`), JSON editing.
9. **Folder-per-post posts stay as folders** (co-located images); the posts URL pattern must map `guide/index.md` → `/posts/guide/`.
10. **Markdown forms:** Phase 2 builds raw snippets from `src/plugins/markdown/manifest.json` for the container/leaf/text directive forms used in content, normalises the single-line `$$…$$` to own-line `$$`, and keeps `mdx-showcase.mdx` (Svelte atoms + Tailwind HTML) out of the rich text editor.
11. **Internal post fields** (`prevUrl`, `nextUrl`, `prevTitle`, `prevSlug`, `nextTitle`, `nextSlug`, `publishedAt`, `updatedAt`) are hidden from editors.

## Open questions

1. **Settings mechanism** — default: the theme's YAML overlay via an in-repo path source (Decision 2), pending Phase 2's feasibility test. Alternative: convert each `*Config.ts` default into an imported data file.
2. **Node version on CloudCannon** — default `build.node_version: "26"` to satisfy `engines >=26.13.0`; if CloudCannon doesn't offer 26, `"24"` (the build passes on 24.22.1 with an engine warning). Or relax `engines` — the user's call.
3. **Which settings domains editors see** — default: the list in Decision 3.
4. **UI-string overrides in the CMS** — default: no; locales stay as they are. Exposing `i18n.yaml` would let editors override strings per locale without touching the language modules.
5. **Demo content** — default: migrate all posts, moments, albums and data as they are (theme demo content), including drafts and encrypted examples.
6. **Encrypted posts/albums** — default: accept that their bodies aren't editable in the Visual Editor (edit in the Content/Source Editor).
7. **Hydration in dev mode** — default: none known (production console clean). User check: run `corepack pnpm dev`, open `/`, `/posts/guide/`, `/projects/`, `/moments/`, `/albums/AcgExample/` with the console open, and report any hydration warning.
8. **Folder-per-post** — default keep folders (Decision 9) rather than flattening and moving 31 images.
9. **`mdx-showcase.mdx`** — default: Source Editor only.
